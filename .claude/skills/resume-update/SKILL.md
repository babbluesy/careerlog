# 이력서 갱신

소스 이력서(`reference/박현우_이력서.pdf`)가 바뀌면 그 내용을 `src/content/` 로 옮긴다.
이전 버전과 비교할 때는 `pypdf` 로 텍스트를 뽑아 UTF-8 파일로 쓴 뒤 diff 한다 (Windows 콘솔은 cp949라 한글을 직접 찍으면 깨진다).

## 1. 내용을 고친다 — `src/content/` 만

화면 문구는 전부 `src/content/` 안에 있다. `.tsx` 를 열 일이 없어야 한다.

| 고칠 것 | 파일 |
| --- | --- |
| 경력·프로젝트 | `experience.ts` |
| 포트폴리오 상세 | `portfolio.ts` |
| 학력(논문 포함) / 수상·교육 | `education.ts` / `awards.ts` |
| 스킬 / 핵심 역량 | `skills.json` / `strengths.json` |
| 이름·직함·소개·반복 문구 | `site.json` |

지켜야 할 것:

- **추측해서 채우지 않는다.** 소스 자료(`reference/`)나 본인 확인에 없는 내용은 `TODO` 로 남기고 **묻는다.**
- **숫자를 손으로 적지 않는다.** About 의 지표 타일(연차·프로젝트 수·논문 수)은 데이터에서 센다. 항목만 추가하면 따라 움직인다.
- 같은 프로젝트를 Experience(요약)와 Portfolio(방법론까지)에 **두 번 쓰지 않는다.** 깊이로 구분하고 `caseStudy: '<id>'` 로 잇는다.

공개 기준 (`CLAUDE.md` 의 "공개 원칙"). 소스 이력서는 마스킹 전 원본이므로 옮길 때 걸러낸다.

- 이메일·전화·생년월일·주소 같은 **식별 정보는 넣지 않는다.**
- **광고주 내부 수치**(상품별 리뷰 수, 군집별 전환율 등)는 옮기지 않는다. 방법론과 결론까지만.
- **코웨이는 탐지 로직의 세부를 쓰지 않는다.** 어떤 신호로 위험 고객을 판단하는지 적으면 회피 방법을 알려주는 셈이다.
  문제 정의·시스템 구조·결과(조회 시간 83% 단축)까지.

## 2. 확인한다

```bash
npm run build          # 타입체크까지 함께 돈다
git status             # apply/, reference/ 가 스테이징되지 않았는지
```

- 화면에서 고친 탭을 열어 본다. 전체 인쇄 조판이 궁금하면 `#/resume` 에서 Ctrl+P 미리보기.
- 마스킹 기준을 넘는 내용(연락처, 탐지 신호, 광고주 수치)이 들어가지 않았는지 다시 본다.
- `CHANGELOG.md` — 사람이 읽을 이유가 있는 변경(새 경력, 프로젝트 추가)이면 `콘텐츠` 로 한 줄 남긴다. 오타 수정은 남기지 않는다.
- 아직 확인받지 못해 `TODO` 로 남긴 항목이 있으면 사용자에게 **무엇이 비어 있는지 말한다.**
